# Measurement integrity

The deliverable is measurements. Everything else supports them.

## Rules

- **Never hand-type a number into a document.** `RESULTS.md` is generated by
  `bench/report.py` from `bench/out/*.json`. If a figure cannot be traced to a
  file, it does not appear in prose.
- **A failed run is a result.** `scripts/run.sh` records startup failures as JSON with
  `"startup": "FAILED"`. Never retry until something succeeds and report only
  that. `fp16-baseline` refusing to start *is* the Part 1 finding.
- **Never average away errors.** Timeouts and failed requests are counted and
  reported per level. A configuration that gets faster by shedding requests has
  not got faster.
- **Report tails, not means.** p50 alone hides queueing, which is the behaviour
  under investigation. p95 and p99 are mandatory for TTFT.
- **When a measurement contradicts a documented hypothesis, change the
  documentation.** Predictions in `README.md` that the data disproved are
  rewritten to match reality and the disagreement is stated, not deleted.
- **Only one variable per comparison.** Identical prompts, output lengths,
  concurrency levels and warm-up across every run, enforced in `scripts/run.sh`.
